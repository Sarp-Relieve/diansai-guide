# 电赛报告写作 Skill

> **触发条件（硬性）**  
> 仅当用户明确要求写/改/生成**电赛技术报告**，或点名本 skill（「电赛报告」「用报告 skill」）时启用。  
> 日常写代码、调参、接线上题 → **不要**自动套用本 skill。

## 〇、使用前必读：本 skill 学什么

本 skill 有两份“范本输入”：

| 来源 | 学什么 | 不学什么 |
|------|--------|----------|
| **PDF《报告格式要求》**（全国统一，无省份差异） | Word 排版、页数、字体、章节职责、附录边界 | 具体题目内容 |
| **示例报告截图（Word 截图）** | **行文逻辑、论证语气、段落骨架、方案比较写法、问题—对策叙事、结论收束** | 具体芯片/参数/成绩/赛题路径（那是别人的题） |

**示例仅是语言与逻辑模板。** 实际报告的题目、模块、算法、数据、创新点可能与示例完全不同——必须按用户当次给定的系统重写，但“怎么论证、怎么比较、怎么写问题与结论”要对齐示例。

## 一、写作启动流程（每次必做）

写正文前，按顺序向用户收齐信息。**缺数据就问，禁止编造测试成绩、PID 参数、器件型号。**

### 1.1 必问清单

1. **赛题**：年份/题号/题名（如 24H 自动行驶小车 / 25E 瞄准装置 / 自定义）
2. **完成范围**：基础要求哪些已做、发挥哪些已做、哪些没做
3. **系统最终方案一句话**（摘要用）
4. **分模块实际选型**（主控/电机驱动/电机/传感器/IMU/显示/电源…）
5. **关键算法与参数**（PID 形式、Kp/Ki/Kd、是否去掉积分、融合方式…）——用户给什么写什么
6. **实测数据**（时间、圈数、误差、成功率）——**用户不给则写“（待填）”，绝不虚构**
7. **调试中真实踩过的坑与对策**（结论 5.2 / 实现问题节用）
8. **创新点 / 心得 / 后续改进**（用户视角，可协助润色但不可杜撰）
9. **输出形式**：Markdown / Word(.docx) / 纯文本大纲
10. **是否有原理图、框图、实测照片**可插入（没有则留图位说明）

### 1.2 硬件默认值（仅当用户未指定且项目基于地猛星时）

三层事实来源（由近及远）：

1. **用户当次实机清单**（最高优先）  
2. **《电赛指北》模块经验** → `references/hardware_zhibei.md`（驱动电流、电机配对、601/八路/泰山派等选型口径）  
3. **`mspm0g-contest` skill**（引脚、协议、例程、SysConfig）  

与示例报告冲突时，**以用户实机 + 指北/mspm0g 为准**，禁止保留示例的 L298N/MPU6050/七路。

| 角色 | 示例报告里写的 | **本 skill 默认（地猛星+指北）** | 处理原则 |
|------|----------------|--------------------------------|----------|
| 主控 | TI MSPM0 / MSPM0G3507 | **MSPM0G3507（立创地猛星）** | 接口宝贵度 UART>PWM>I2C≥串行>GPIO |
| 电机驱动 | L298N | **TB6612**（配 310，VM≈7.4V，峰值约 1.2A） | **必须改**；大电机/12V 改 **AT8236**（峰值约 6A） |
| 电机 | 笼统直流减速 | **310**：7.4V、堵转≈1.5A、减速比≈1:20；或 **513**：12V、堵转≈3.2A、1:30 | 按实机；310↔TB6612，513↔AT8236 |
| IMU | MPU6050 | **汇电籽-601（ICM42688+M0，UART 姿态）** | **必须改**；MPU6050/6500 仅作用户备选或方案一 |
| 灰度 | 七路线性灰度阵列 | **敢为八路**（辅助板串行 4 线 或 GPIO 并口） | **必须改**；五路只宜作方案一 |
| 视觉（可选） | （示例无） | **泰山派** OpenCV / YOLO，UART 回传结果 | 题面要视觉才写；运维步骤不进正文 |
| 舵机（可选） | （示例无） | **MR996R** 等 PWM 舵机（四轮转向/机构） | 差速车无舵机则不写 |
| 底盘 | 前置万向轮+后驱差速 | 按用户实车（差速 / 舵机转向） | 灵活 |
| 声光 | 蜂鸣器+LED | **BEEP=PA15 低响，LED=PA14 高亮**（或用户指定） | 灵活 |
| 显示 | （示例弱写） | OLED SSD1306 可选 | 有则写，无则不硬加 |
| 拓展板 | （示例弱写） | 地猛星拓展板承载驱动/编码/灰度座 | 总框图可提及，一般不必单独方案章 |

> 用户若用完全不同平台（STM32/树莓派/无车云台等）：**整份默认表作废**，全部以用户清单为准，只保留本 skill 的**格式与行文逻辑**。  
> 《电赛指北》是**硬件说明**，不是报告范文：口语、备赛运维、AI 工具链**不得原样写入正式报告**，需改写成工程书面语（见 `hardware_zhibei.md` §11）。

### 1.3 与示例“同构不同词”

- 示例结构可复用（引言→方案论证→设计实现→测试→结论）。
- 示例里的 **R=40cm、2.51s、55.79s、A→B→C→D、L298N、MPU6050、七路灰度** 等，**禁止在无用户确认时原样写入**新报告。
- 用户给了对应数据，再写入；没给就占位。

## 二、Word 排版规范（全国统一，硬性）

生成 Word 或提供排版说明时严格遵守（**不分省份**）：

| 项 | 要求 |
|----|------|
| 正文页数 | **≤ 8 页**（不含附录） |
| 附录 | 页数不限；电路图、PCB、流程图、源码等放附录 |
| 大标题（摘要等） | 三号宋体加黑 |
| 小标题 | 四号宋体加黑 |
| 正文 | 小四号；中文宋体，英文/数字 Times New Roman |
| 行距 | 固定值 **22 磅**，纵向 |
| 公式 | **公式编辑器**（Word 方程），禁止截图公式滥竽充数 |
| 图名/表名 | 五号，与正文字体一致；**图名在图下，表名在表上** |
| 页边距 | 每页上方 **≥ 3 cm 空白**，空白内无文字；建议其余边距 2.5cm；A4 |
| 页码 | 右下；**第 1 页从正文起编** |
| 摘要 | **≤ 300 字**；一般只要中文摘要，不强制英文摘要 |
| 正文禁忌 | **正文不贴大段源码**；软件用流程图 + 文字说明 |

### 2.1 直接导出 docx（推荐）

skill 内置脚本：`scripts/md_to_docx.py`

```bash
# 依赖（首次）
pip install python-docx

# 用法
python ~/.claude/skills/电赛报告/scripts/md_to_docx.py 报告.md -o 技术报告.docx
python ~/.claude/skills/电赛报告/scripts/md_to_docx.py 报告.md -o 技术报告.docx --title "基于MSPM0G3507的自动行驶小车"
```

脚本自动处理：

- A4、上边距 3cm、页脚右下 PAGE 域、起始页码  
- 一级题（`##`）三号宋体加粗；`###`/`####` 四号加粗  
- 正文小四、中文宋体/英文 Times New Roman、固定行距 22 磅、首行缩进  
- `![图名](path)` 插图 + 五号居中图名；`表x`+Markdown 表 → 表名在上  
- `$...$` / `$$...$$` 居中占位，并提示用 Word 公式编辑器重录  

**写报告工作流（默认）：**

1. 先产出完整 Markdown（结构按本 skill）  
2. 用户要 Word 时 **必须跑脚本生成 docx**，不要只丢 md  
3. 提醒用户：复杂公式在 Word 里用公式编辑器重录；图路径用绝对路径或相对 md 的路径  

输出纯 Markdown 时仍可在文首附「Word 排版对照说明」，但优先给 docx。

## 三、章节职责（来自 PDF）+ 示例逻辑映射

PDF 规定的报告骨架 + 示例教你的**每章怎么写**：

```
[封面/参赛信息 — 按当届通知表格，本 skill 可略]
摘要（≤300字）
1 引言
2 系统方案和设计
   2.1 系统总框图
   2.x 各模块方案论证与选择（重点：比较）
   2.n 软件流程图
3 设计实现
   3.1 理论分析 / 关键参数与控制律
   3.2 实现与调试中的问题及对策
4 测试方案与测试结果
5 结论
   5.1 系统完成情况
   5.2 存在的问题与原因分析
   5.3 心得体会与进一步努力方向
参考文献（可选，正文页数紧时从简）
附录（图、源码、PCB…）
```

章节名可随题目微调（云台题可把“循迹”换成“瞄准/跟踪”），但 **“方案比较 → 理论→实现问题→测试→结论三段”** 的逻辑链不能丢。

## 四、行文逻辑圣经（示例的真正价值）

以下规则从示例报告的**遣词与论证方式**抽象而来。写任何题目都要遵守。

### 4.1 总语气

- **竞赛工程体**：客观、肯定、偏“已完成并验证”，避免博客式口语、避免 AI 套话（“值得一提的是”“赋能”“打造”）。
- **先约束、后方案**：每段先点明赛题约束/难点，再引出对策，最后落到“本系统采用…”。
- **比较必有裁决**：方案一/方案二并列后，必须有「综合比较：…本系统选择方案×」句式收束。
- **数据服从叙事**：成绩为结论服务；没有数据就写清测试方法，把表格留给用户填。

### 4.2 摘要（≤300 字）逻辑链

按此顺序压进一段或两段，勿写成长引言：

1. 做了什么系统（对象 + 主控型号）  
2. 最终实施方案（底盘/驱动/传感器/控制策略关键词）  
3. 具体实现手段（闭环形式、融合、状态机等）  
4. **主要创新点**（1～2 个，要具体）  
5. 结果（用用户数据；无数据则“完成题目规定的基础/发挥要求”）  
6. 一句结论（平稳/精度/达标）

### 4.3 引言逻辑链（对齐示例 §1）

示例节奏：

1. **领域一句**（自动行驶/瞄准/跟踪在智能制造或相关领域的意义）——1～2 句即可，勿宏大叙事灌水。  
2. **本题任务句**：基于 ×× MCU 设计××装置/小车。  
3. **难点枚举**（示例风格：用分号或短句堆叠硬约束）  
   - 物理约束（小半径、投影不离线、尺寸、功率…）  
   - 传感约束（无摄像头 / 必须视觉 / 光照…）  
   - 控制约束（高速过弯、闭环精度、实时性…）  
   - 任务约束（跨段调度、节点识别、声光、模式切换…）  
4. **对策总括句**：「为了克服上述难题，本系统采用了 A、B 和 C，通过严格的方案论证和参数整定，实现了…」  
5. 不在引言展开公式与引脚。

### 4.4 系统总框图节（§2.1）逻辑

- 先用 1 句总述组成：「系统主要由 A、B、C、D 等部分组成。」  
- 再给框图（用户无图则输出 **Mermaid/ASCII 框图** + 「图 1 系统总框图」图名位）。  
- 框图信息流要完整：供电、传感反馈、控制量、执行器、人机/声光。  
- 模块名用**最终选型**（TB6612、ICM42688/汇电籽-601、八路灰度…），不要写示例的 L298N/MPU6050/七路。

### 4.5 方案论证节（§2.2～2.5）——示例的核心笔法

**每一模块**固定四段式（示例 2.2 主控 / 2.3 底盘 / 2.4 动力 / 2.5 传感器 同构）：

```
【模块名】方案选择
方案一：采用……。优点…。缺点…（紧扣本题约束，说明为何不够）。
方案二：采用……。优点…（紧扣本题约束，说明如何更好满足）。
综合比较：为……（重申关键约束），本系统选择方案二。
（可选）附图：接口连线图 / 原理要点，图题五号。
```

写作细则：

- **方案一常是“看似能做但踩题约束”的常见方案**（51 单片机、四轮阿克曼、步进电机、普通红外开关、L298N、仅编码器盲走等）——按**本题**重新挑选反面方案，禁止无脑复制示例反面。  
- **方案二是最终方案**，优点必须映射到题面原话式约束（“投影不得离线”“用时越少越好”“无摄像头”…）。  
- 裁决句模板（保持肯定语气）：  
  - 「综合比较以上方案，为严格遵守“…必须…”的竞赛规则，并充分发挥…硬件优势，本系统选用方案二作为…。」  
  - 「综合比较：为确保…时的物理稳定性与…精度，本系统选择方案二。」  
- 同一报告内模块数量随系统复杂度增减；**重点模块详写，次要模块可合并**，但主控/执行器/关键传感器三类尽量都有比较。

#### 地猛星小车类题目的默认比较素材（可改）

仅在用户做差速循迹小车且未另指定时作素材库；细节参数见 `references/hardware_zhibei.md`。云台/双芯/视觉题另组织方案一/二。

| 模块 | 方案一（弃） | 方案二（取） | 裁决抓手 |
|------|-------------|-------------|----------|
| 主控 | STC89C51 等 8 位机，算力/外设不足 | MSPM0G3507，Cortex-M0+，多路 ADC/PWM/UART | 赛题指定 TI MSPM0 + 高速 PWM 差速与多串口传感 |
| 底盘 | 传统四轮阿克曼/舵机转向，转弯半径大、易拖胎 | 前置万向轮+后轮差速（或用户实车） | 小半径弯 / 投影压线 |
| 驱动+电机 | 步进高速扭矩跌；或 L298N 发热压降大 | **TB6612 + 310 电机（7.4V）**；动力不够再升 **AT8236 + 513（12V）** | 峰值电流裕量、体积、PWM 差速、编码器闭环 |
| 循迹传感 | 普通五路/开关红外，难连续量化偏差 | **敢为八路**（串行省 IO 或并口 GPIO） | 无摄像头下给 PID 横向误差；呼应 IO 宝贵 |
| 姿态/盲走 | 仅编码器推算或 MPU6050 I2C | **编码器 + 汇电籽-601（ICM42688，UART）航向闭环** | 无黑线盲走直线度 |
| 视觉（题需要时） | 主控内硬扛图像，实时性差 | **泰山派 OpenCV/YOLO**，结果 UART 回传 M0 | 双芯分工、共地、主控专注运动控制 |

### 4.6 软件流程图节

- 先 1 句：「程序流程图如图×所示。」  
- 流程逻辑对齐示例图 4 的**状态机味道**（即使题目不同）：  
  `初始化/模式选择 → 循环读传感器 → 是否满足节点/停障条件 → 是则声光/停车/切换航段 → 否则按当前模式（循迹 PID / 盲走融合 / 瞄准 / 跟踪）计算控制量 → 输出执行器 → 任务是否结束`  
- 正文只放流程图 + 文字；源码进附录。

### 4.7 设计实现 · 理论分析（§3.1）逻辑

示例笔法：

1. 点明控制策略名称（位置式离散 PID / 串级 / 纯 PD / 模糊…——以用户实际为准）。  
2. **给出核心公式**（公式编辑器编号 (1)(2)…）。  
3. **逐符号定义**：「式(1)中，u(k)为…；e(k)为…；Kp…」。  
4. 说明 **e(k) 如何从传感器得到**（加权平均、哪一路权重更大、八路如何映射到横向偏差等）。  
5. 工程化取舍（示例：高速下为避免积分饱和取 Ki=0，主要靠 PD；P 给回复力，D 给阻尼）。  
6. 用 1～2 句闭环到赛题现象（抑制小半径入弯超调、保证投影不离线 / 光斑误差等）。

**禁止**：贴大段工程代码当“理论”；堆砌未使用的高级算法名。

### 4.8 实现与调试问题及对策（§3.2）逻辑

示例固定节奏（可写多条，每条都很短）：

```
在执行赛题要求（×）的……时，出现了【现象】。
解决办法：引入/改用【手段】，与【原手段】融合/替换，实现了【闭环效果】，大大提高了【指标】。
```

- 问题必须来自用户真实调试；用户没说则问，或写框架让用户补。  
- 对策要可检验（多传感器融合、参数分区、硬件抗干扰、状态机防抖…）。

### 4.9 测试方案（§4）逻辑

严格按示例四段，可增删仪器：

1. **测试仪器**：精度写出数量级（秒表 0.01s、卷尺 1mm、手机录像…）。  
2. **测试方法**：初始位姿如何放置、如何触发任务、观察哪些现象（节点声光、是否离线、是否偏航）。  
3. **数据处理**：重复次数、取平均、误差来源分析——示例为「每项 3 次取算术平均」。  
4. **测试结果**：表格（任务 | 次数1 | 次数2 | 次数3 | 平均 | 是否达标）。无数据 → 空表 +「（数据由实测填写）」。

### 4.10 结论三节（§5）逻辑——示例尾声结构

**5.1 系统完成情况**  
- 主控 + 系统定位一句。  
- 「经过严谨的系统测试，本…不仅以…完成了基础…，更在…条件下，依靠…，实现了…发挥任务。」  
- 用用户成绩；强调平稳、声光正确、**100% 完成已宣称的要求**（未完成的不要写满完成）。

**5.2 存在的问题与原因分析**  
- 先扬后抑：「尽管各项指标均已达标，但在…后期/极限工况下发现…」。  
- 给工程原因（电池内阻压降导致同 PWM 力矩下降、单环 PD 缺电压补偿、机械打滑…）。  
- 示例句式可仿：「由于当前系统仅采用了基于…的…，未能引入…，从而在…状态下暴露出…不足。」

**5.3 心得体会与进一步努力方向**  
- 心得：理论→绘板→底层代码的工程闭环；对「多传感器融合」「某架构外设」的认识加深。  
- 展望 **恰好两条**（示例是两条）：更高级控制（串级 PID/模糊 PID…）+ 专用电源稳压/动态监控（或视觉/结构——按题目改）。  
- 语气真挚、具体，避免空洞“提高自己”。
